# 新一期竞品周报制作指南（喂给 AI 后照做即可）

> **使用方法**：把本文全文 + 同目录 `AGENT.md` 一起发给你的 AI 助手（Codex/Copilot/Claude 等），然后按第 1 章准备素材，之后每一步都有可以直接复制的对话模板。
> 站点：`https://xmonitor.doc.nie.netease.com/competitor-weekly/`
> 原理：纯静态网页，所有内容来自 `competitor-weekly/data/*.json`。**做新一期 = 更新几个 JSON 文件 + 改一行代码 + push**，不涉及任何后端部署。

---

## 1. 开工前准备（一次性 + 每期素材）

### 1.1 环境（只做一次）

| 要什么 | 检查/安装 |
|---|---|
| Git | 命令行执行 `git --version` 有版本号即可 |
| Node.js（仅用于校验 JSON/本地预览，非必须） | `node --version`；没有可跳过，校验步骤可让 AI 代做 |
| GitLab 仓库权限 | 让管理员把你加进 `xmonitor/xmonitor.doc.nie.netease.com`（Reporter 及以上），并在 GitLab 个人设置创建 Access Token（勾 `read_repository`+`write_repository`） |
| 一个 AI 助手 | 能读写本地文件的最好（Codex/各类 IDE 插件）；纯对话式 AI 也可以，只是要手动复制文件内容 |

首次克隆（token 替换成你的）：

```bash
git clone https://oauth2:<你的TOKEN>@gitlab.nie.netease.com/xmonitor/xmonitor.doc.nie.netease.com.git
cd xmonitor.doc.nie.netease.com
git remote set-url origin https://gitlab.nie.netease.com/xmonitor/xmonitor.doc.nie.netease.com.git
```

### 1.2 每期要收集的素材（给 AI 的"原料"）

| 素材 | 用在哪 | 没有怎么办 |
|---|---|---|
| 本期周报正文（PDF/Word/飞书文档，含每个竞品的运营动作、活动分析、玩家反馈） | 核心运营内容、数据表亮点、首页卡片 | 必须有，否则本期做不了 |
| 数据表：各竞品周流水（万元）、日均DAU（万）、DAU峰值（万）及环比% | `periods.json` 当期 items | 缺哪个产品就填 `null`，页面显示"未披露" |
| 日级数据表（日期-DAU-流水，xlsx） | `daily-metrics.json` 详情页趋势图 | 可后补，先不做趋势也行 |
| 本期综述（一段行业总览文字） | `periods.json` 的 `overview` | 可让 AI 根据正文帮你起草，人工改 |
| 配图（活动截图、数据截图，webp 优先） | `core-images.json` 核心内容配图 | 可后补 |
| 用户画像截图（抖音粉丝画像，可选） | `audience-profiles.json` | 可不做 |
| 本期周一日期（周期 key，如 20260629） | 所有文件 | 必须有 |

## 2. 总流程（一张图）

```
pull 最新代码 → 建新周期框架 → 逐模块喂素材给 AI 生成 JSON → 本地校验/预览
→ git 提交并 push → 等 1-2 分钟线上核对
```

全程只有第 4 步需要你自己判断，其余都可以让 AI 执行。

## 3. 分步操作 + AI 对话模板

### Step 0 同步最新版本（每期必做，防覆盖他人）

```bash
cd xmonitor.doc.nie.netease.com
git pull --rebase origin main
```

### Step 1 建新周期框架

对 AI 说：

> 阅读 `competitor-weekly/AGENT.md` 第 4.1、4.2 节。本期周期 key 是 `<20260629>`（周一），日期范围 `<2026.06.29—2026.07.05>`。请：
> 1. 在 `competitor-weekly/data/reports.json` 数组最前面插入新一期对象（参考现有第一条格式，pages 填 `null`）；
> 2. 在 `competitor-weekly/data/periods.json` 复制上期 `"20260622"` 的条目，key 改为 `"20260629"`，`dataWindow` 改为新日期范围，items 里所有数值字段改成 `null`，`note/keywords/summary/overview` 先留空；
> 3. 把 `competitor-weekly/app.js` 顶部 `const state={period:'20260622'` 的日期改成 `'20260629'`（这是唯一允许改代码的地方，只改这一处）。
> 改完逐文件做 JSON 合法性校验。

人工复核一眼 diff，然后**先 push 这一次框架**（可选但推荐）：

```bash
git add competitor-weekly/data/reports.json competitor-weekly/data/periods.json competitor-weekly/app.js
git commit -m "周报框架：新建 20260629 周期"
git pull --rebase origin main && git push origin main
```

### Step 2 填数据表（周流水/DAU/峰值）

把数据表（截图转文字或直接贴表格）发给 AI：

> 按 `AGENT.md` 第 4.1 节，把以下本期数据填入 `competitor-weekly/data/periods.json` 的 `"20260629"` 条目对应产品（产品 id 对照见 AGENT.md 4.6）。flow 单位万元，dau/peak 单位万，Delta 是环比%。素材里没有的指标保持 `null`，不要估算。
> 同时按 `app.js` 里 `HIGHLIGHT_SHORT` 的现有格式，为每个有运营动作的产品写一句 ≤30 字的运营亮点（活动名+核心动作，不写数据表现），更新该常量。
> 数据：<贴表格>

### Step 3 填日级趋势数据（可后补）

> 按 `AGENT.md` 第 4.3 节，把这份 xlsx 的日级数据合并进 `competitor-weekly/data/daily-metrics.json`：每个产品追加本期日期行 `[日期, DAU, 流水]`，缺列填 `null`，保持日期升序、不重复。
> 数据：<贴表格或给文件路径>

### Step 4 生成核心运营内容（最花时间的部分，AI 主力）

把本期周报正文发给 AI（太长就按产品分次发）：

> 阅读 `AGENT.md` 第 4.4 节与 `competitor-weekly/data/core-items.json` 中 `"wz"` 的现有条目，学习格式。这是本期 `<产品名>` 的周报正文素材：<贴正文>。
> 请按素材提炼为本期条目：`period` 填 `"20260629"`，`type` 从给定枚举选，`text` 用 `○`主题/`–`要点/`·`细节/`“`玩家原话 的层级写，忠实于素材、不要扩写编造。追加到 `core-items.json` 对应产品数组前面，校验 JSON。

配图（可选）：

> 把这几张图转成 base64 webp，按 `AGENT.md` 4.4 的规则写入 `competitor-weekly/data/core-images.json`，并在刚才的正文条目里按现有格式引用。图片文件在 `<路径>`。

### Step 5 首页卡片情报与综述

> 根据本期正文素材，更新 `competitor-weekly/data/intel.json` 中本期有异动的产品条目（event/time/conclusion/verdict/tone，参考现有格式），并为 `periods.json` 的当期 `overview` 起草一段本期综述（行业总览 + 重点产品表现，可用 `<b>` 加粗重点）。素材：<贴正文或概要>

### Step 6 本地校验与预览

```bash

node -e "['reports','periods','daily-metrics','core-items','intel'].forEach(f=>{JSON.parse(require('fs').readFileSync('competitor-weekly/data/'+f+'.json','utf8'));console.log(f,'ok')})"

npx serve .
# 浏览器打开 http://localhost:3000/competitor-weekly/ 检查：首页数据表、卡片、详情页趋势、核心运营内容
```

### Step 7 提交并发布

```bash

git add competitor-weekly/data/daily-metrics.json competitor-weekly/data/core-items.json competitor-weekly/data/core-images.json competitor-weekly/data/intel.json

git pull --rebase origin main     # 再同步一次，防同事并发
git push origin main
```

### Step 8 线上验收（push 后 2 分钟）

打开 `https://xmonitor.doc.nie.netease.com/competitor-weekly/`（Ctrl+F5 强刷）逐项核对：

- [ ] 监测周期默认显示新一期
- [ ] 数据表数值、环比、亮点短句正确；缺数据显示"未披露"而不是 0
- [ ] 首屏卡片是本期的
- [ ] 详情页趋势图包含本期日期，悬浮提示正常
- [ ] 核心运营内容默认展开，层级/配图正常
- [ ] 本期综述无乱码

## 4. 常见问题

| 问题 | 处理 |
|---|---|
| push 被拒 fetch first | `git pull --rebase origin main` 后再 push；有冲突就让 AI 帮你解（保留双方内容） |
| 改错了已 push | 不要 force push：`git revert <错误提交sha>` 后再 push |
| 线上 404 | 先等 2 分钟强刷；再去 GitLab → CI/CD → Pipelines 看 pages 是否绿色 |
| 本地双击 html 打不开数据 | 正常现象，file:// 不能读 JSON，用 Step 6 的 npx serve |
| 素材不全能不能先发 | 能。缺的部分填 `null` 先发布，之后同一流程补 push 即可 |
| 图片太大 | 先压成 webp（宽度 ≤1200px），再 base64；单张尽量 <200KB |
